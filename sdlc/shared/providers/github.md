# GitHub

`fetch` goes through the `gh` CLI only: it holds the credentials, and nothing here reads, prints or stores a token. Coordinates are `owner` (namespace level) and `repository` (product level).

- **Mirror shape.** `raw/raw.json` holds `meta`, `issue` (the REST issue, labels included), `comments`, `parent`, `sub_issues`, `blocked_by`, `blocking` and `attachments`. Bodies and comments are Markdown. A parent, sub-issue or blocker can live in another repository: read its `repository_url`.
- **No parent is `null`.** The parent endpoint answers 404 for an issue without one; that is not a failure. Every other failure aborts the fetch and writes nothing, so a mirror is never half there. `gh` drops a connection now and then; each call is tried twice. A call that gets no answer within 120 seconds (`SDLC_CLI_TIMEOUT` overrides) is a failure too, with a hint; for an attachment it is listed in the report.
- **Revision.** GitHub has none, so `ticket.json` `fingerprint.sha256` hashes the title, body, state, label names, comment ids and bodies, the parent, and the number and state of each sub-issue and blocker. `updated_at` is left out: it moves without anything in the mirror changing.
- **Revision check.** `fetch <ref> --check` is the read-only revision check: it writes nothing and prints `{ref, ticket_dir, changed, status, reason?, recorded, live, coordinates, last_fetched_at}`. `status` is `unchanged`, `changed`, `never_mirrored` (no recorded fingerprint; `changed` is true, as nothing vouches for the mirror), `stale_mirror` (a fingerprint but no `raw/raw.json`: the mirror predates this shape, so `changed` is true and `reason` says to refresh with `/sdlc:intake <ref>`; upstream is not asked) or `local` (no upstream; `changed` is false). Here `live` is the fingerprint recomputed from the live issue by the same function `fetch` records with, from the same reads (issue, comments, parent, sub-issues, blockers); it downloads nothing. A failure is reported as `fetch` reports it, with nothing written.
- **A pull request is not an issue.** The issues endpoint answers a pull request number too; `fetch` refuses it.
- **Attachments.** Every URL in the body and comments that is a GitHub upload (`github.com/user-attachments/...`, `github.com/{owner}/{repository}/files/...`, `user-images.githubusercontent.com`) is recorded with its URL and the name its author gave it, whether or not it downloads. The URL must be `https` on exactly `github.com` or `user-images.githubusercontent.com`, with no userinfo or port; any other host is not an attachment and is never passed to `gh`. A download is `gh api <url>`, with `gh` supplying its own authentication; a failure is listed in the report and never aborts the fetch. Verified downloading images from a public repository; uploads in a private repository were not verified. An `assets` upload has no file name, so it is saved as `{uuid}` plus an extension read from the file's first bytes (png, jpg, gif, pdf, zip; none otherwise); other uploads as `{id}-{file name}`. A file already in `raw/` is the same attachment and is kept on refresh.

## Writing (for `submit`)

Always `--repo {owner}/{repository}`, never the repository the invocation directory happens to belong to. Bodies go through `--body-file` from a scratch file outside the ticket directory, never inline: quoting and non-ASCII text break in a shell.

- **Create.** `gh issue create --repo ... --title ... --body-file ... [--label ...]`; it prints the new issue's URL, whose last segment is the number. Tags do not exist here: labels are the only tagging.
- **Edit.** `gh issue edit {n} --repo ... --title ... | --body-file ... | --add-label ... | --remove-label ...`. State is `gh issue close {n}` (optionally `--reason "not planned"`) or `gh issue reopen {n}`; a GitHub issue is only open or closed.
- **Acceptance criteria** have no field: they are the `## Acceptance Criteria` section of the body, ending at the next heading of the same or a higher level. To change the description or the criteria, send the whole new body, built from the mirror's `issue.body` with only that part replaced; what follows the section is carried through.
- **Labels.** Compare case-insensitively. `create` and `edit` fail for a label the repository lacks (`gh label list --repo ... --json name` shows what exists); creating one is a second write, so ask first.
- **No revision guard.** GitHub cannot make an edit conditional on the issue not having moved, so `fetch --check` runs immediately before the write; a very small window remains.
